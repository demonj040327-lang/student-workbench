# WhisperLiveKit 本机部署与测试

日期：2026-10-24。范围：在 Apple Silicon Mac 上独立部署语音识别服务，验证真实 WebSocket 流式识别。现已接入学生端课程页面，操作步骤见 [课堂录音与翻译使用说明](课堂录音与翻译使用说明.md)。本说明侧重底层服务的安装与独立测试。

## 当前部署

- 项目：[QuentinFuxa/WhisperLiveKit](https://github.com/QuentinFuxa/WhisperLiveKit)。本次固定源码提交 `eb92c115ee7abc1e161b0b2159da31785b0f5566`，项目版本 `0.2.26`。
- 源码：`.backups/open-source-review/WhisperLiveKit/`。
- 独立 Python：`.backups/whisperlivekit-env/`，Python 3.12；没有修改课程平台的 Node 依赖或全局 Python 包。
- 模型与缓存：`.backups/speech-models/`；原始音频、转写事件、版本清单与测试结果：`.backups/speech-evaluation/`。这些路径均不进 Git，不随公开构建分发。
- 使用 MLX 编码器与默认 SimulStreaming 策略；当前默认还包含原生 Whisper 解码器，并非声称全部推理都在 MLX 上运行。
- 使用 macOS 系统证书信任解决 Python 下载证书链问题，没有关闭 HTTPS 证书校验。
- 语音服务脚本与课程页面集成已合入 `main`；同伴互助仍留在独立分支。

## 打开与启动

本机测试页面：<http://127.0.0.1:8000/>。点击上方录音按钮并允许麦克风，即可测试英文实时转写，再次点击停止并等待尾部文字处理完成。

该地址是开源项目自带的独立测试界面。工作台的录音、编辑、翻译与讲解使用另行实现的课程侧栏，不在该独立页面中。此配置只绑定本机回环地址，手机和其他同学尚不能直接联网访问。

在项目根目录重新启动：

```sh
tools/start-local-speech.sh
```

默认使用 `small.en` 英文模型；快速对照基础模型可执行：

```sh
SPEECH_MODEL=base.en tools/start-local-speech.sh
```

端口被占用时，关闭旧服务，或临时更换端口：

```sh
SPEECH_PORT=8001 tools/start-local-speech.sh
```

首次安装或在另一台 Apple Silicon Mac 复现：先准备 `uv`、Python 3.12 与 FFmpeg，再执行：

```sh
tools/install-local-speech.sh
```

安装脚本固定第三方源码版本，已有不同版本的源码会被保留并提示，不强制重置。首次启动需要下载权重；下载不属于本次实时延迟统计。Python 依赖可能随包源变化，本次实际版本保存在本机 `environment.txt`，不声称仅固定源码就能逐字节重建环境。

## 测试方法

1. 通过 macOS Daniel 英音、Samantha 美音，合成 HCI 与神经网络概念说明。它们是已知文字的受控输入，不是真实课堂录音。
2. 使用 [whisper.cpp 的公开 JFK WAV 样本](https://github.com/ggml-org/whisper.cpp/blob/master/samples/jfk.wav)，检验真人声音。脚本固定音频 SHA-256，远程文件变化时拒绝默默采用。
3. 对 HCI 音频添加可复现的 10dB 白噪声；它不是教室人声混响的完整模拟。
4. 使用 5 秒静音，检查是否凭空输出文字。
5. 将三个语音样本加间隔接成一条超过一分钟的连续音频，检查跨越 30 秒后的持续输出与结束处理。
6. 按音频实际采样时间发送 PCM16、16kHz、单声道数据，每 0.5 秒一包，使用绝对发送时间，不能把“文件识别得很快”冒充“实时识别”。一条 WebSocket 会话持续到完整音频结束，不按课件页数分段。
7. 浏览器验证使用测试 WAV 作为虚拟麦克风，经过真正的麦克风采集接口、音频处理与本机模型；它不等于已测用户物理麦克风或真实教室收音。

准备测试音频与复测：

```sh
.backups/whisperlivekit-env/bin/python tools/prepare-speech-fixtures.py
.backups/whisperlivekit-env/bin/python tools/test-realtime-speech.py --model small.en --samples jfk hci ml hci-noisy silence continuous
```

测试需要一段完整音频的实际播放时间。生成的 `*-events.json` 保留每次真实服务响应，`*-result.json` 保存最终文字、参考文字、音频哈希和计时。不要在测速时同时跑另一组模型推理。

## 如何理解结果

详细数值见同目录《实时语音实测结果》。词错误率 WER 是字词替换、删除和插入次数除以参考词数；本次忽略大小写、标点、连字符与撇号的写法差异。0% 只描述该小样本，不能叫作“课堂识别准确率 100%”。

“第一批字幕时间”从测试音频开始算起，受到开头静音和说话内容影响，不是每个词的平均延迟。“结束后等待”是发送完音频到服务确认最终输出的时间。所有模型已启动、下载并预热，统计不包含冷启动。

## 接入 workbench 的建议

流程：浏览器持续采集 → 同时保存完整录音和向本机识别器发送流 → 原文确认后交给学生自己的 DeepSeek → 连续译文 → 学生修改确认 → 全文生成课程讲解。

内部流式传输、模型缓冲与增量提交是实时处理机制，不要求把用户的录音或笔记拆成课件小节。原文、译文都应以连续文稿显示，翻页不切断录音。

实现编辑时必须把原始识别结果与用户编辑稿分开：后续字幕只能追加，不得覆盖人工纠错。字幕尚未稳定的部分单独显示。生成讲解的输入必须取确认后的译文，不能仍然读取最初自动结果。

本次没有配置或调用真实 DeepSeek API，没有花费语音云 API 额度；也没有把学校 ELM 的教师凭据用于学生翻译。下一步接入需使用学生自己的 DeepSeek Key，在本机配置界面输入，不能提交到 GitHub。

## 尚未验证

- 一整节 50–90 分钟课程、远距离教室收音、多人同时说话及专业术语覆盖率。
- 手机锁屏、切后台、设备断线、空间不足时完整录音恢复。
- 真实 DeepSeek 翻译质量、额度和端到端延迟。课程页面中的保存、编辑和接口流程现已有单独回归，模型响应采用模拟测试，详见使用说明。
- 多用户并发、公网部署和学校账户权限。

本轮证明本机流式识别可运行，并提供有限样本的效果依据；以上环节应在产品接入后分别验收。
