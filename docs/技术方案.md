# Student Workbench 技术方案

**2026-10-14 · 实现目标与后续 API 设计**

本文区分已实现的本机 Demo 与后续多用户产品方案。2026-10-14 增加逐份材料解析、课程中文讲解、ELM 学习路线与问答，详见 [课件学习与 ELM](课件学习与ELM.md)。当前未公开上线。

## 1. 本次 Demo

前端方案采用 **React + TypeScript + Vite**，手机优先响应式网页，桌面可展开更多信息。课程、任务、步骤、答题与界面状态通过明确类型组织。设计重点是课程身份可见、主操作可点击、暂停续学与内容清楚；无需为原型训练模型。

已实现：创建课程；在当前课程下保存文件；手动创建 coursework 并填写步骤；展示周任务、记录完成/卡点与顺延；运行人工核对的 HCI、CGR、AML、MLP lecture 预设短关卡。课程与文件通过 `courseId` 关联，用户上传文件原件存 **IndexedDB**；课程、步骤、疑问和关卡完成状态存 localStorage。预置真实课件另由本地开发服务器提供。

真实预设内容由 `src/courseContent.ts` 提供，保存课程、三个基础模块/MCQ、人工复习计划与材料索引。题目以 `sourceId` 关联材料，以 `sourcePage` 关联阅读器页序；CGR 原 PPTX 与辅助讲义的页码分别说明。课件原文件只供本地查看，必须排除出版本控制与公开部署。[课程内容依据](课程材料与关卡依据.md)记录实际文件与页码。

新增 `server/study-api.mjs` 和 Python 解析器：PDF/PPTX/DOCX/TXT/MD 提取真实页序文字，按文件建立独立阅读路线和答题记录；本机原文检索与 ELM 语义解释分开标识。ELM 生成计划经 JSON 结构、选择题索引及页码覆盖检查，问答检索仅当前文件。密钥只在服务端，当前复用已有学校配置，不训练模型。自动 coursework 要求拆分仍未实现。无账户身份认证，不等于支持多用户安全隔离；跨设备同步也未包含。

浏览器本地数据可能受配额、隐私模式和清理影响。文件保存失败应给出错误并保留重试路径；本地保存不等于云备份。实际支持的类型、大小、预览方式和持久化效果需逐项验证。

## 2. 当前本机服务与后续生产分层

**网页 → 受认证的应用 API → 文件解析与内容服务 → 模型供应商 API → 校验与学生确认 → 课程任务存储。**

本机后端已采用 Node/Vite middleware + Python 文件解析；多用户生产服务的认证、云托管和数据库仍待团队选定，不把候选方案写成已有部署。API 密钥只在服务端保管，不放入网页代码或提交到仓库。文件原件可存私有对象存储，课程、要求、任务和答题记录存数据库；后台处理按任务状态返回进度与错误。

核心数据对象建议：`Course`、`Material`、`SourceReference`、`CourseworkRequirement`、`RubricCriterion`、`TaskStep`、`LearningUnit`、`Question`、`Attempt`、`PlanRevision`。生产对象至少带 `ownerId`、`courseId`、版本与创建/修改时间。

- `SourceReference` 保留文件 ID、原文片段、页码/段落或转写时间戳；不存在的出处不能通过校验。
- `TaskStep` 保留产出、依赖、要求关联、预计用时、截止日、状态及确认情况。
- `Attempt` 保留首次答案、提示使用与结果；不能以完成布尔值推导掌握。
- `PlanRevision` 保留原安排、修改原因与确认结果；顺延不覆盖官方截止日期。

## 3. PDF/PPTX 解析与生成

当前 PDF 提取文字与阅读器页序，PPTX 按真实播放顺序提取幻灯片文字。图像、讲者备注、OCR、PPTX 转 PDF/图片预览属于后续扩展。复杂公式、图表、动画和转写误差需要单独处理，不能将“成功读取文件”当成“成功理解全部内容”。

先解析并保存来源，再向现有模型请求结构化草稿。无需自建或训练大模型。示例输出内容包括：要求/评分项、学习目标、步骤、题目选项、答案依据、来源引用与待确认项。使用 JSON schema 或等价结构校验；检查枚举、引用有效性、题目答案、依赖循环、日期与必要字段。校验失败应重试或返回待审查草稿，不能悄悄补值。

coursework 缺少 rubric、字数或官方学习目标时，输出“待学生确认”，并区别材料明示要求与模型推测。上传文档只作为待处理数据，其中出现的指令不能改变系统规则、触发任意代码或获得其他课程资料。当前采用文件内词项检索，含课程中英术语映射，未建向量数据库；课程资料增多后可改成向量检索，仍需当前用户、课程和材料权限过滤。

## 4. 缓存、成本与版本

建议以用户/课程、文件内容哈希、解析版本、目标设置和生成模板版本组成缓存键。材料更新使相关来源与题目标记为需要复核；缓存不能跨用户泄露私人课程材料，也不能让错误结果永久不可修改。

解析/转写/生成分开记录状态，控制文件大小、请求频率和每次生成关数。费用、响应时间与模型选择需用实际供应商和样例测试测量，目前没有成本或延迟承诺。确定性任务管理、保存和顺延不需要每次调用模型。

## 5. 账户、权限与删除

生产版本的所有材料、题目、任务和缓存访问都必须检查 `ownerId` 与课程权限；对象 ID、前端筛选或不可猜链接不能代替授权。文件默认私有，不公开课件，不默认用于模型训练或共享知识库。共享功能如增加，需要单独明确对象与接收者。

删除路径应覆盖原文件、解析文字、转写、生成结果、检索索引和关联缓存；对备份保留期与第三方服务数据处理作明确说明。使用对象 URL 的预览结束后及时释放。输入文本在渲染时转义，上传文件不能作为脚本执行。存储加密、认证与服务配置要经过部署验证后才能宣称实现。

## 6. 本地录音与后续问答/转写

课程问答以当前页、选区及获准材料为上下文，区分材料内容与补充解释，回答附出处。未转写录音时，不能声称知道老师实时说了什么。缺乏依据时返回需核对的信息。

本次录音由主动按钮启动，显示状态与停止操作，录音文件可在课程资料播放与删除；尚无暂停按钮。Chrome 模拟麦克风已验证保存、切课释放与课程归属，真实硬件和移动 Safari 未验证。采集前说明课堂许可、上传去向及保存方式；不允许录音时支持获准提供的字幕。麦克风与系统音频是不同权限与兼容性问题，需要目标浏览器实测。录音切片转写后保留时间戳，翻页记录只作为页码关联草稿，可由学生纠正。

转写专业词与公式可能错误，出题前应显示待核对片段。只把重复强调标记为课堂重点，不能自动判定考试范围。录音中的他人发言和私人信息应按明确规则处理；使用外部服务前说明数据处理，而不是自动把全部音频上传。

## 7. 验收清单

| 验收层次 | 应实际检查的内容 |
|---|---|
| 前端与手机 | 窄屏无横向溢出；按钮与输入可用；键盘/焦点清楚；桌面布局正常 |
| 用户状态 | 课程创建、当前课程文件归属、手动步骤、完成/顺延、暂停与刷新续学 |
| 本地文件 | 保存成功与失败提示；刷新后存在；删除可用；浏览器配额失败不丢失其他任务 |
| 题目与反馈 | 真实预设题来源准确、正确/错误解释、完成持久化；尚未持久化完整作答历史，不把完成视为掌握 |
| 本机 API / ELM | 真实提取、结构与引用校验、当前文件检索、模型请求失败保留原路线、密钥不进入浏览器 |
| 后续 AI | coursework brief/rubric 自动拆分、录音转写、图像/OCR 与跨课程评估 |
| 后续安全 | 跨用户/跨课程访问拒绝；密钥不进入前端；原件与衍生数据删除 |

基础界面、真实文件提取、来源检索、每文件进度续学和删除缓存已做本机浏览器与接口检查，见 [开发验证](开发验证-20261014.md)。模型调用使用真实学校 ELM 另做测试。实际录音设备、浏览器配额异常、移动 Safari、多用户认证与生产部署仍未验证。
