## 结论

当前教师端具备作为参赛功能原型演示的条件。官方将功能 Demo、代码、原型或视频列为强烈推荐的可选材料；正式提交仍需要三页报告。因此“网页可演示”和“参赛材料已齐全”是两件事。

## 已有可展示流程

1. 英文默认入口，学生/教师身份选择，中文和英文切换。
2. 创建课程、修改课程、管理课程周次。
3. 上传 PDF/PPTX/DOCX，分别生成学习草稿和选择题。
4. 生成队列允许连续提交与页面切换，失败任务可重试；完成结果为草稿。
5. 教师修改讲解、知识点、步骤、题目、选项和出处，再检查发布。
6. 学生视角预览；预览答题不进入学生学习记录。
7. 上传 Coursework，生成介绍及提取日期；教师核对后发布。
8. 学生反馈与按课程分类的讨论区、待回复提醒。

当前 `feat/peer-learning` 分支的录屏精选视图保留 7 份资料；具体名单及恢复完整资料库的方法见 [演示资料精选与录屏路线](演示资料精选与录屏路线.md)。以下 37 份指历史完整回归范围。

真实课程回归结果记录在本机 `data/local-demo-library/测试报告.md`：37 份教学资料经过实际 ELM 生成流程及结构校验。该结果证明流程可运行，不代表 100% 知识准确率或学习效果提升。

## 演示边界

- 身份选择是演示入口，不是学校正式账号认证。
- 反馈与讨论目前只在同一浏览器共享，并非跨设备班级系统。
- 生成队列运行在网页中，关闭或刷新页面会中断未完成任务。
- `localhost:5175` 只能供运行该项目的本机使用，不能直接作为外部评委可访问的在线链接。可提交屏幕录像，或另行准备可运行源码/部署。
- 图片、扫描内容和公式图像并未由当前文字解析器完整理解；讲解和答案需教师检查。
- 7 份较大的 CGR PPT 通过本机资料库导入，不代表普通上传通过 25 MB 上限。
- 现有中文 AI 草稿和用户编写的中文内容不会因切换界面语言而自动改写；新生成任务遵循当前选择的语言。
- 课程原件与模型输出保存在本机忽略目录，不作为公开代码内容分发。
- 不宣称平台已经与学校学习系统集成、自动提交作业或证明学习成效。

## 建议展示顺序

建议录制约 2–3 分钟的视频（这是项目建议，不是官方时长要求）：

1. 英文登录入口选择 Teacher，展示课程总览与周次管理。
2. 上传一个小型示例文件，启动草稿生成，再提交题目任务或另一份文件，展示非阻塞队列。
3. 打开已完成结果，编辑一处讲解，补生成题目，学生视角预览，最后发布。
4. 展示一份 Coursework 草稿和日期确认，再展示待回复提醒与教师答疑。
5. 简短说明本机原型边界及后续真实账户、持久任务与图文解析计划。

可以使用准备好的真实测试结果展示等待后的界面，但应标明是预先生成的数据，不将其冒充即时模型响应。录像展示课程材料时仅呈现必要片段。

## 提交前需要确认

- 最终三页报告是否完成，并按模板填写作者、机构与联系邮箱。
- 报告中是否提供可用的视频、原型或代码入口；本机 localhost 不能作为外部在线演示链接。
- 如分享源码，是否同步了本次本机修改并提供环境配置说明；不得公开 API Key 和本机教学资料。
- 在提交表单中是否确实完成提交。本轮没有替用户提交。
