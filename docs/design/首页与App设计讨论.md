## 已确认的方向

- 手机可安装，同时保留电脑网页。
- 首页优先展示学期时间轴、不同课程的大作业以及各自完成度。
- 浅色统一：浅灰背景、白色时间轴与列表、少量课程色。
- 之前的 HCI、CGR、AML、MLP 课程演示退出当前应用。
- 首页开发与 AI 功能分工：本阶段重点是呈现、交互和后端数据接口，不扩展录音、游戏、自动排课等范围。

## 参考产品：看哪一个界面，借鉴什么

## 建议的首页结构

### 1. 学期栏

学期选择、当前周次、设置入口。学期起止日由用户确认。

学期时间已过比例可以保留你之前要求的精确数字，但建议主数字便于扫读，更多小数作为次级显示或精确模式。是否默认持续显示 8 位小数仍可讨论。

### 2. 学期时间轴——首页最重要的区域

- 横轴：当前学期的日历月份；保留今天标线及“定位今天”。
- 纵向按课程分组，每份大作业独立一行。
- 横条的位置和长度表达计划开始日期至截止日期；条内另有清楚标示的完成比例。
- 不让“已过学期比例”与“作业完成比例”混成同一种指标。
- 无明确日期的作业进入“待安排”，不自动伪造时间条。
- 里程碑可用小标记表达，先只展示关键节点，避免移动端太拥挤。
- 完成度计算方式对用户可见；缺少估时或权重时按步骤数计算，不暗示完成度等于成绩、掌握率或真实工作量。
- 时间过了 50%、任务做了 20% 本身不足以判定延期；风险提示依据截止时间和未完成节点，首版不用无依据的“落后”判断。

### 3. 大作业进度列表

每行固定提供：课程名称 / 作业名称 / 截止日期 / 完成比例 / 下一步。

点开后手机使用底部详情面板，电脑使用侧边详情面板。第一版支持查看、勾选步骤、修改日期。拖动改期属于后续增强，不作为唯一操作方式。

### 4. 本周要推进的事项

放在时间轴和大作业进度之后，按截止时间或课程筛选，帮助学生从总览进入具体行动。不会盖过首页的学期视角。

## 手机和电脑怎样对应

| 手机 App | 电脑网页 |
|---|---|
| 顶部简短的学期信息；时间轴占首屏主体 | 时间轴横向展开，旁边可留详情区 |
| 全学期缩略视图与“本月 / 学期”缩放切换；放大后仅图内部横向滑动 | 更多月份同时可见，课程名固定在左侧 |
| 点击作业从底部展开详情，保留当前时间轴位置 | 点击作业打开右侧详情，减少整页跳转 |
| 底部导航建议：首页 / 课程 / 计划 | 可用侧栏或简洁顶栏；页面对象保持一致 |
| 新建操作放在明确的“添加”入口 | 同一操作可有完整文本按钮 |

以上布局为建议。底部导航名称、默认缩放和信息密度仍可在高保真设计中讨论。

## 视觉方向建议

已确认：浅灰背景、白色工作区、深色文字；一种主操作色，课程用少量辅助色。课程色同时配课程名，不靠颜色独自表达身份。

时间轴可以用轻边框和分隔线形成秩序，减少大块纯黑、宣传标题、背景渐变和每条任务一张大卡片。字号按正文、辅助信息和标题分级，重点留给作业名、日期和进度。

## 可以复用的组件与需要自己实现的部分

建议先统一选用一套 shadcn/ui 的实现变体；不要同时堆叠 Base UI、Radix 和 Ionic 的同类弹层组件。

| 用途 | 参考 / 可复用来源 | 自己需要实现的部分 |
|---|---|---|
| 作业完成条 | [shadcn Progress](https://ui.shadcn.com/docs/components/progress) | 进度计算、数值说明、课程颜色、空进度状态 |
| 手机底部详情 | [shadcn Drawer](https://ui.shadcn.com/docs/components/drawer) | 作业详情内容、关闭后焦点恢复、返回键与路由状态 |
| 课程筛选、时间范围切换 | [Radix Tabs](https://www.radix-ui.com/primitives/docs/components/tabs) 或选定的 shadcn 同类组件 | 状态、筛选语义、手机布局；两种来源择一保持一致 |
| 日期选择、确认弹层 | shadcn 的 Calendar / Date Picker / Dialog | 截止日规则、开始晚于结束的提示 |
| 空状态、加载占位、错误重试 | shadcn 的 Empty / Skeleton，加自己的业务文案 | 新用户零数据、接口失败、离线提示和重试行为 |
| 学期时间轴 | 自己实现 React + CSS Grid / SVG | 时间坐标、课程分组、缩放、今天标线、里程碑与可访问点击区域 |
| Coursework 行、学期栏 | 自己的业务组件 | 这是产品辨识度的主要来源，不套用管理后台模板 |

shadcn/ui 仓库使用 [MIT 许可](https://github.com/shadcn-ui/ui/blob/main/LICENSE.md)；复用时保留相应许可说明，并核对实际安装组件依赖。当前 Drawer 文档默认分支已使用 Base UI，存在其他变体，实施时应按当时的实际文档固定一种实现；不直接沿用旧教程中关于 Vaul 的假设。

## 做成可安装 App 的实现形式

建议沿用 React + TypeScript + Vite 开发前端，采用 [Capacitor](https://capacitorjs.com/docs) 生成 iOS / Android 原生工程。Capacitor 官方支持接入已有现代 JavaScript 项目，并通过原生容器和插件接入设备能力。

- 网页与 App 共享业务组件和样式，适配不同宽度。
- App 还要处理安全区、系统返回键、键盘遮挡、文件选择、弹层手势和本地持久化；打包成功不等于这些细节全部通过。
- Android 安装包、iOS 开发设备 / 测试分发与商店发布分别验收；不把“网页加到主屏幕”当作已完成原生安装包。
- 手机不能访问电脑上的 localhost 学习服务。App 需要连接组员提供的 HTTPS 后端；学校 ELM 密钥只保存在服务端。
- 一套前端并不自动带来跨设备同步。同步课程和进度仍需要账号、后端持久化及冲突处理。

目前尚未安装 Capacitor、创建原生工程、真机安装或提交应用商店；本稿仅提出实施路线。

## 首页开发可以独立交付的内容

1. 课程与作业数据类型、进度计算规则，与负责后端的组员约定数据结构。
2. HomePage，以及 SemesterSummary、SemesterTimeline、CourseworkRow、CourseFilter、AssignmentDetails 等独立组件。
3. 手机与电脑布局、空状态、加载状态、错误重试及真实用户数据展示。
4. 与学期设置、作业详情、上传入口的导航连接。
5. 在设计确认后再接 API 和 App 容器。

页面先从数据适配层读数据，组件不要写死课程或联网方式。开发用固定样本应放在独立 fixture 中，且明确标为样本，不再次默认注入真实用户空间。

## 首页效果预览（2026-10-22）

用户要求使用课程示例展示前端和时间轴后，已增加 `/?demo=1` 独立示例模式。包括认知心理学、世界史与史料研究、应用统计学、交互设计，共六份虚构作业，显示 0%、20%、40%、60%、80%、100% 的完成比例。
